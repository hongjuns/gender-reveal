# Feature Specification: 공유 링크 기반 젠더리빌 플로우(v2)

**Feature Branch**: `002-shareable-link-flow`

**Created**: 2026-07-25

**Status**: Draft

**Input**: User description: "기존 gender-reveal 앱을 v2로 업데이트. 현재 플로우: 어플리케이션 접속 →
step1 작성 → step2 클릭 → step3 확인. 변경할 플로우: 유저1(생성자)은 step1 작성 후 '링크 생성'을 클릭해
고유 공유 링크를 발급받아 유저2에게 공유하고, 유저2(참여자)는 공유받은 링크로 접속해 step2 화면부터
시작하여 step3까지 확인한다(step1은 노출되지 않음). step1 입력 필드는 태명, 출산예정일, 받는사람(이름),
성별이며, 유저2가 링크로 접속하면 유저1이 입력한 값이 그대로 반영되어 step2~3에 표시되어야 한다. 링크는
생성일 기준 7일간 유효하며, 만료된 링크로 접속 시 안내 화면을 표시한다. 하나의 링크로 여러 명이 접속해도
동일한 내용을 보아야 하며, 존재하지 않는 링크로 접속 시 404 에러를 처리해야 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 링크 생성 및 공유 (Priority: P1)

예비 부모(생성자)가 태명, 출산예정일, 받는사람 이름, 성별을 입력한 뒤 '링크 생성'을 클릭하면 고유한
공유 링크가 발급되고, 이 링크를 받는사람(참여자)에게 전달할 수 있다.

**Why this priority**: 이 플로우 전체의 시작점이며, 이 기능 없이는 v2의 핵심 변경사항(공유 기반 경험)이
성립하지 않는다.

**Independent Test**: step1의 4개 필드를 모두 채우고 '링크 생성'을 클릭했을 때, 고유한 링크(URL)가
발급되어 화면에 표시(및 복사 가능)되는지 확인하는 것으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** step1 입력 폼이 비어 있는 초기 화면, **When** 태명·출산예정일·받는사람·성별을 모두 입력하고
   '링크 생성'을 클릭, **Then** 고유한 공유 링크가 발급되고 화면에 노출된다.
2. **Given** 링크가 발급된 상태, **When** 생성자가 해당 링크를 복사, **Then** 다른 사람에게 그대로
   전달할 수 있는 완전한 URL 형태로 제공된다.
3. **Given** 필수 입력 필드(태명·출산예정일·받는사람·성별) 중 하나라도 비어 있는 상태, **When** '링크
   생성'을 클릭, **Then** 링크가 발급되지 않고 미입력 항목에 대한 안내가 표시된다.
4. **Given** 링크가 성공적으로 발급된 상태, **When** 생성자가 해당 화면에 머무름, **Then** 생성자도
   step2 화면(풍선 인터랙션)으로 진입하여 참여자와 동일한 경험을 이어갈 수 있다.

---

### User Story 2 - 공유 링크를 통한 참여자 접속 (Priority: P1)

참여자(유저2)가 전달받은 공유 링크로 접속하면 step1 화면 없이 곧바로 step2(풍선 인터랙션) 화면부터
시작하며, 생성자가 입력한 태명·출산예정일·받는사람·성별 값이 그대로 반영되어 step2~step3에 표시된다.

**Why this priority**: v2의 핵심 목표인 "생성자만 정보를 입력하고, 참여자는 결과를 체험한다"는 경험을
완성하는 단계로, User Story 1과 함께 있어야 실제 공유 시나리오가 완결된다.

**Independent Test**: 유효한 공유 링크로 접속했을 때 step1 화면이 노출되지 않고 step2 화면부터 시작되며,
생성자가 입력했던 태명 등이 반영된 문구가 표시되는지 확인하는 것으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 생성자가 발급한 유효한 공유 링크, **When** 참여자가 해당 링크로 접속, **Then** step1 입력
   화면 없이 곧바로 step2(풍선 인터랙션) 화면이 표시되며, 생성자가 입력한 태명이 안내 문구에 반영된다.
2. **Given** step2 화면에서 풍선을 10번 터치, **When** 마지막 터치가 완료, **Then** 생성자가 입력한
   성별·받는사람·출산예정일 값이 반영된 step3 결과 화면으로 전환된다.
3. **Given** 동일한 공유 링크, **When** 서로 다른 여러 사람이 각자 접속, **Then** 모두 동일한 태명·
   출산예정일·받는사람·성별 내용을 보게 된다(단, 각자의 풍선 터치 진행 상태는 서로 독립적이다).

---

### User Story 3 - 만료/존재하지 않는 링크 처리 (Priority: P2)

참여자가 생성일로부터 7일이 지난 링크나 애초에 존재하지 않는 링크로 접속했을 때, 각각 명확한 안내
화면(만료 안내, 404 에러)을 보게 된다.

**Why this priority**: 핵심 플로우(User Story 1, 2)가 동작한 다음에 필요한 예외 처리로, 사용자가 잘못된
상태에서 혼란을 겪지 않도록 보완하는 역할이다.

**Independent Test**: 생성 후 7일이 지난 링크로 접속 시 "만료된 링크" 안내가, 존재한 적 없는 임의의
링크 값으로 접속 시 404 에러 화면이 노출되는지 확인하는 것으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 생성일 기준 7일이 경과한 공유 링크, **When** 참여자가 해당 링크로 접속, **Then** step2/3
   내용 대신 "만료된 링크" 안내 화면이 표시된다.
2. **Given** 생성일 기준 정확히 7일 이내(예: 6일 23시간 경과)의 공유 링크, **When** 참여자가 접속,
   **Then** 정상적으로 step2 화면부터 시작된다.
3. **Given** 발급된 적 없는 임의의 링크 식별자, **When** 사용자가 해당 URL로 접속, **Then** 404 에러
   화면이 표시된다.

---

### Edge Cases

- 링크 식별자 형식은 맞지만 실제로 발급되지 않은 값으로 접속하면 존재하지 않는 링크와 동일하게 404로
  처리한다.
- 만료된 링크와 존재하지 않는 링크는 서로 다른 안내 화면(만료 안내 vs. 404)으로 구분되어야 한다.
- 참여자가 step2 화면을 새로고침하거나 재접속해도, 만료되지 않은 동일 링크라면 동일한 입력 내용이 다시
  반영되어야 한다(단, 풍선 터치 진행 상태는 초기화될 수 있다).
- 생성자가 링크 생성 후 브라우저를 닫았다가 다시 그 링크로 접속해도 참여자와 동일하게 step2부터
  시작한다(생성자 전용 재입력 경로는 없다).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 생성자가 태명·출산예정일·받는사람(이름)·성별 4개 필드를 입력하는 step1 화면을
  제공해야 한다.
- **FR-002**: 시스템은 4개 필드가 모두 입력된 경우에만 '링크 생성' 동작을 허용해야 하며, 하나라도
  누락되면 링크를 발급하지 않고 사용자에게 안내해야 한다.
- **FR-003**: 시스템은 '링크 생성' 클릭 시 각 링크마다 고유한 식별자를 가진 공유 링크(URL)를 발급해야
  한다.
- **FR-004**: 시스템은 발급된 공유 링크에 step1 입력값(태명·출산예정일·받는사람·성별)을 연결하여
  저장해야 한다.
- **FR-005**: 시스템은 발급된 공유 링크를 생성자가 화면에서 확인하고 복사/공유할 수 있는 형태로 제공해야
  한다.
- **FR-006**: 시스템은 유효한 공유 링크로 접속한 사용자에게 step1 화면을 노출하지 않고 step2(풍선
  인터랙션) 화면부터 시작해야 한다.
- **FR-007**: 시스템은 유효한 공유 링크로 접속했을 때, 해당 링크에 저장된 태명·출산예정일·받는사람·성별
  값을 step2 및 step3 화면에 그대로 반영해 표시해야 한다.
- **FR-008**: 시스템은 링크 생성 완료 시 생성자도 동일한 링크의 step2 화면으로 진입시켜, 참여자와 동일한
  풍선 인터랙션 및 결과 확인 경험을 제공해야 한다.
- **FR-009**: 시스템은 각 공유 링크의 유효 기간을 생성 시각 기준 7일로 관리해야 한다.
- **FR-010**: 시스템은 생성 후 7일이 경과한 공유 링크로 접속 시, step2/step3 내용 대신 "만료된 링크"임을
  알리는 안내 화면을 표시해야 한다.
- **FR-011**: 시스템은 존재하지 않는(발급된 적 없는) 링크 식별자로 접속 시 404 에러로 처리해야 한다.
- **FR-012**: 시스템은 동일한 공유 링크로 접속하는 모든 사용자에게 동일한 태명·출산예정일·받는사람·성별
  내용을 제공해야 한다(사용자별로 내용이 달라지지 않는다).
- **FR-013**: 시스템은 각 접속자의 step2 풍선 터치 진행 상태(터치 횟수 등)는 접속자별로 독립적으로
  관리해야 하며, 다른 접속자와 공유하지 않는다.
- **FR-014**: 시스템은 공유 링크에 저장된 입력 내용(태명·출산예정일·받는사람·성별)을 생성 이후 변경할
  수 없는 불변 데이터로 취급해야 한다.

### Key Entities *(include if feature involves data)*

- **공유 링크(Share Link)**: 생성자가 발급한 고유 링크. 고유 식별자, 생성 일시, 만료 일시(생성
  일시+7일), 연결된 입력 내용(아래 이벤트 정보)으로 구성된다.
- **이벤트 정보(Event Info)**: 공유 링크 하나에 연결된 태명, 출산예정일, 받는사람(이름), 성별 값의
  집합. 링크 생성 시 확정되며 이후 변경되지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 생성자는 step1 입력 완료 후 10초 이내에 공유 가능한 링크를 발급받을 수 있다.
- **SC-002**: 참여자는 공유 링크로 접속했을 때 별도 입력 없이 3초 이내에 step2 화면(생성자의 입력값이
  반영된 상태)을 확인할 수 있다.
- **SC-003**: 동일한 공유 링크로 접속한 서로 다른 사용자 100%가 동일한 태명·출산예정일·받는사람·성별
  내용을 확인한다.
- **SC-004**: 생성 후 7일이 지난 링크로의 접속 시도 100%가 만료 안내 화면으로 연결되며, 존재하지 않는
  링크로의 접속 시도 100%가 404 화면으로 연결된다.
- **SC-005**: 참여자 중 90% 이상이 안내 없이도 step2 화면만으로 무엇을 해야 하는지(풍선 터치) 이해하고
  행동을 완료한다.

## Assumptions

- 링크 생성 직후 생성자의 화면 흐름: 생성자는 링크 발급 후 별도 대기 화면 없이 바로 자신도 동일한
  링크의 step2 화면으로 진입해 참여자와 동일한 경험(풍선 터치→결과 확인)을 이어간다고 가정한다. 생성자
  전용 대시보드나 "공유만 하고 대기" 화면은 이번 범위에 포함하지 않는다.
- step2 풍선 터치 진행 상태(터치 횟수)는 접속자(브라우저)별로 독립적으로 관리하며, 여러 명이 같은
  링크로 접속하더라도 서로의 터치 진행 상황에는 영향을 주지 않는다고 가정한다. 공유되는 것은 태명·
  출산예정일·받는사람·성별 등 "콘텐츠"뿐이다.
- 공유 링크에 저장된 이벤트 정보(태명 등)는 생성 이후 수정하거나 링크를 재발급할 수 없는 불변 데이터로
  가정한다. 다른 내용을 공유하려면 처음부터 새로 입력해 새 링크를 생성해야 한다.
- 공유 링크는 웹에서 접근 가능한 URL 형태로 발급되며, 별도의 로그인/계정 없이 링크 소지만으로 접속 가능
  하다고 가정한다.
- 링크 유효기간(7일)은 생성 시점을 기준으로 계산하며, 타임존은 기존 애플리케이션의 기준(한국 표준시)을
  따른다고 가정한다.
- 하나의 공유 링크는 하나의 이벤트 정보(태명 등)에만 연결되며, 링크 재사용이나 다중 이벤트 연결은
  범위 밖이라고 가정한다.
- 만료된 링크와 존재하지 않는 링크에 대한 안내 화면의 구체적인 문구/디자인은 이후 구현 단계에서
  기존 앱의 톤앤매너에 맞춰 정한다고 가정한다.
