추가(01, 02, 03...), 첫 칸 외에는 X로 삭제 가능, '젠더리빌 풍선 만들기'로 한 번에 생성.

gender_reveal_events 행 = 받는 사람 1명. code 칼럼으로 묶음(공통 정보 중복 저장 허용, 수정 기능
없음). code는 관리 링크용 비밀값으로 추측 불가한 랜덤 값이며 받는 사람 응답/링크에 절대 노출
금지. 기존 행은 랜덤 code로 백필, NOT NULL, 일반 인덱스(unique 아님). 삭제: id와 code가 모두
일치할 때만 삭제, 삭제 시 댓글도 함께 삭제. 만료: 최초 생성 시 묶음 내 모든 풍선의 만료 시각을
동일하게 맞춤(생성+7일). 풍선마다 1회에 한해 7일 연장 버튼. 관리 링크 자체는 만료 없음."

## Clarifications

### Session 2026-11-03

- Q: 이미 만료된 풍선도 연장할 수 있는가? → A: 가능. 만료 후 연장 시 새 만료 시각은 연장한 시점 + 7일
  (만료 전 연장은 기존 만료 시각 + 7일). 풍선당 1회 제한은 동일.
- Q: 한 번에 만들 수 있는 받는 사람 수 상한은? → A: 10명.
- Q: Step1의 패스키 영역과 사람 아이콘은? → A: 둘 다 제거한다. 관리 화면 진입은 관리 링크로만 한다.
- Q: Step3 로딩 화면 노출 시간은? → A: 저장이 빨리 끝나도 최소 2초 보여준 뒤 관리 화면으로 이동한다.
- Q: 연장 여부를 별도 칼럼으로 저장하는가? → A: 저장하지 않는다. 만료 시각 > 생성 시각 + 7일이면 연장한 풍선으로 본다.
  (DB에서 만료 시각을 직접 늘린 풍선은 연장한 것으로 판단된다.)
- Q: Step4 관리 링크 모달 닫기 방식은? → A: X 버튼 없음. "링크 복사하기"를 눌러 복사에 성공하면 모달이 사라진다.

## Glossary

- **풍선**: 받는 사람 1명에게 보내는 젠더리빌 이벤트 1건. 받는 사람마다 고유한 공유 링크를 가진다.
- **풍선 묶음**: 한 번의 생성으로 함께 만들어진 풍선들. 태명·예정일·성별이 같다.
- **관리 코드**: 풍선 묶음을 식별하는 추측 불가능한 비밀값. 만든 사람만 알아야 한다.
- **관리 링크**: 관리 코드를 포함한, 만든 사람이 풍선 관리 화면으로 돌아오기 위한 링크.
- **공유 링크**: 받는 사람이 풍선을 터뜨리고 결과를 보는 기존 링크(풍선별 1개).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 받는 사람 여러 명에게 보낼 풍선을 한 번에 만들기 (Priority: P1)

만든 사람은 태명·출산 예정일·성별을 한 번만 입력한 뒤, 받는 사람 입력칸을 `+` 버튼으로 원하는
만큼 늘려(받는 사람 01, 02, 03 …) 이름을 적고 "젠더리빌 풍선 만들기"를 눌러 받는 사람 수만큼의
풍선을 한 번에 만든다. 만드는 동안 "{태명}의 풍선이 만들어지고 있어요." 화면이 보이고, 생성이 끝나면
풍선 관리 화면으로 이동한다.

**Why this priority**: 여러 풍선을 만드는 것이 v3의 핵심 가치다. 이 기능이 없으면 관리할 대상도 없다.

**Independent Test**: 받는 사람 3명을 입력해 생성한 뒤, 관리 화면에 3명이 표시되고 각 공유 링크로
접속했을 때 각자의 이름이 담긴 풍선이 열리는지 확인하는 것만으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 공통 정보 입력 화면(Step1), **When** 태명·예정일·성별을 모두 입력하고 "받는 사람 입력"을
   누르면, **Then** 받는 사람 입력 화면(Step2)으로 이동한다. 하나라도 비어 있으면 이동하지 않고 비어 있는
   항목을 표시한다. 이 화면에는 패스키 입력 영역과 사람 아이콘이 없다.
2. **Given** 받는 사람 입력 화면, **When** 처음 진입하면, **Then** "받는 사람 01" 입력칸 1개가
   보이고 이 칸에는 삭제(X) 버튼이 없다.
3. **Given** 받는 사람 입력칸이 1개 이상 있는 상태, **When** `+` 버튼을 누르면, **Then** 다음
   번호("받는 사람 02" …)의 빈 입력칸이 추가되고, 추가된 칸에는 삭제(X) 버튼이 있다.
4. **Given** 받는 사람 입력칸이 3개인 상태, **When** 02번 칸의 X를 누르면, **Then** 그 칸이
   사라지고 남은 칸의 번호가 01, 02로 다시 매겨지며 입력한 내용은 유지된다.
5. **Given** 받는 사람 3명의 이름을 모두 입력한 상태, **When** "젠더리빌 풍선 만들기"를 누르면,
   **Then** "{태명}의 풍선이 만들어지고 있어요." 로딩 화면(Step3)이 최소 2초 보이고, 공통 정보(태명·예정일·
   성별)는 같고 받는 사람만 다른 풍선 3개가 하나의 묶음으로 만들어지며, 3개 모두 같은 만료 시각(생성 시각
   + 7일)을 가진 뒤 풍선 관리 화면으로 이동한다.
6. **Given** 입력칸 중 하나라도 비어 있는 상태, **When** "젠더리빌 풍선 만들기"를 누르면, **Then**
   풍선은 하나도 만들어지지 않고 비어 있는 칸이 표시된다.
7. **Given** 생성 도중 오류가 발생한 경우, **When** 생성이 실패하면, **Then** 일부 풍선만 만들어진
   상태로 남지 않고(전부 생성 또는 전부 미생성), 로딩 화면에서 받는 사람 입력 화면으로 돌아가 입력값이
   유지된 채 다시 시도하라는 안내가 보인다.

### User Story 2 - 관리 화면에서 받는 사람별 링크 복사하기 (Priority: P1)

생성 직후 만든 사람은 "풍선이 생성되었어요! 링크를 복사하여 풍선 이벤트를 선물하세요." 화면에서
받는 사람 목록을 보고, 각 행의 "링크 복사하기"로 받는 사람별 공유 링크를 복사해 전달한다.

**Why this priority**: 공유 링크를 꺼내지 못하면 만든 풍선을 아무에게도 보낼 수 없다. US1과 함께
있어야 최소 기능이 성립한다.

**Independent Test**: 관리 화면에서 02번 받는 사람의 "링크 복사하기"를 누르고, 복사된 링크로 접속했을
때 02번 받는 사람의 풍선이 열리는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 풍선 관리 화면, **When** 화면이 열리면, **Then** 묶음 안의 받는 사람이 생성 순서대로
   "받는 사람 01, 02 …" 번호와 함께 보인다.
2. **Given** 관리 화면의 특정 받는 사람 행, **When** "링크 복사하기"를 누르면, **Then** 그 받는
   사람의 공유 링크가 클립보드에 복사되고 복사 완료 안내가 보인다.
3. **Given** 복사된 공유 링크, **When** 받는 사람이 접속하면, **Then** 기존과 동일하게 풍선 터뜨리기
   → 결과 → 댓글 흐름이 동작하며, 화면·응답 어디에도 관리 코드나 관리 링크가 나타나지 않는다.
4. **Given** 클립보드 접근이 막힌 환경, **When** "링크 복사하기"를 누르면, **Then** 복사 실패
   안내와 함께 링크를 직접 선택해 복사할 수 있는 방법이 제공된다.

### User Story 3 - 관리 링크를 보관하고 나중에 관리 화면으로 돌아오기 (Priority: P1)

로그인이 없으므로, 만든 사람은 관리 화면에 처음 들어왔을 때 "현재 페이지로 돌아오기 위해 아래
링크를 복사하여 별도 보관해주세요" 모달에서 관리 링크를 복사해 둔다. 모달에는 닫기 버튼이 없고, 링크를
복사해야 모달이 사라진다. 나중에 이 관리 링크로 접속하면
같은 풍선 관리 화면이 열린다.

**Why this priority**: 관리 링크가 없으면 생성 직후 화면을 닫는 순간 링크 복사·삭제·연장을 할 수
없게 된다. 관리 기능 전체의 진입점이다.

**Independent Test**: 생성 직후 모달에서 관리 링크를 복사하고 브라우저를 닫은 뒤, 새 창에서 관리
링크로 접속해 같은 받는 사람 목록이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 풍선 생성 직후 관리 화면 진입, **When** 화면이 열리면, **Then** 관리 링크 보관 모달이
   자동으로 뜨고 관리 링크가 표시된다.
2. **Given** 관리 링크 보관 모달, **When** "링크 복사하기"를 누르면, **Then** 관리 링크가 클립보드에
   복사되고 복사 완료 안내가 보인다.
3. **Given** 관리 링크 보관 모달, **When** "링크 복사하기"로 복사에 성공하면, **Then** 모달이 사라지고
   관리 화면이 보인다. 모달에는 닫기(X) 버튼이 없고, 바깥 영역 클릭이나 Esc로도 닫히지 않는다.
4. **Given** 클립보드 접근이 막힌 환경, **When** 모달의 "링크 복사하기"를 누르면, **Then** 모달은
   유지되고 복사 실패 안내와 함께 링크 입력칸을 직접 선택해 복사할 수 있다. 이 경우에 한해 "직접
   보관했어요" 같은 보조 버튼으로 모달을 닫을 수 있다.
5. **Given** 이전에 보관한 관리 링크, **When** 언제든(생성 후 7일이 지난 뒤 포함) 접속하면,
   **Then** 해당 묶음의 관리 화면이 열린다. 관리 링크 자체에는 만료가 없다.
6. **Given** 관리 링크로 나중에 다시 접속한 경우, **When** 화면이 열리면, **Then** 보관 모달은
   자동으로 뜨지 않는다(생성 직후 진입에서만 자동 노출).
7. **Given** 존재하지 않거나 잘못된 관리 코드가 담긴 링크, **When** 접속하면, **Then** "찾을 수
   없는 페이지" 안내가 보이고 어떤 풍선 정보도 노출되지 않는다.

### User Story 4 - 받는 사람 풍선 삭제하기 (Priority: P2)

만든 사람은 관리 화면에서 잘못 만들었거나 더 이상 필요 없는 받는 사람의 풍선을 "삭제"로 지운다.
삭제된 풍선의 공유 링크와 그 풍선에 달린 댓글은 함께 사라진다.

**Why this priority**: 잘못 만든 풍선을 정리하는 보조 기능이다. 생성·공유(P1)가 먼저 갖춰져야 한다.

**Independent Test**: 관리 화면에서 한 받는 사람을 삭제한 뒤, 목록에서 사라지고 그 공유 링크로
접속하면 "찾을 수 없는 페이지"가 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 관리 화면의 특정 받는 사람 행, **When** "삭제"를 누르면, **Then** 삭제 여부를 한 번 더
   확인받는다.
2. **Given** 삭제 확인, **When** 확인을 누르면, **Then** 해당 풍선과 그 풍선의 댓글이 영구 삭제되고
   목록에서 사라지며 남은 받는 사람의 번호가 다시 매겨진다.
3. **Given** 삭제된 풍선의 공유 링크, **When** 누군가 접속하면, **Then** "찾을 수 없는 페이지"가 보인다.
4. **Given** 관리 코드를 모르는 사람, **When** 풍선 id만으로 삭제를 시도하면, **Then** 삭제는 거부되고
   풍선은 그대로 남는다(풍선 id와 관리 코드가 모두 맞아야만 삭제).
5. **Given** 묶음의 마지막 남은 풍선, **When** 삭제하면, **Then** 관리 화면에는 "남은 풍선이 없어요"
   안내와 새 풍선 만들기로 가는 버튼이 보인다.

### User Story 5 - 풍선 링크 기간 1회 연장하기 (Priority: P3)

만든 사람은 관리 화면에서 받는 사람별로 공유 링크 유효기간을 한 번에 한해 7일 연장한다.

**Why this priority**: 받는 사람이 늦게 확인하는 경우를 위한 편의 기능이다. 없어도 핵심 흐름은 동작한다.

**Independent Test**: 관리 화면에서 한 받는 사람의 "연장"을 누른 뒤, 그 풍선의 만료일이 7일 늘어나고
연장 버튼이 다시 누를 수 없는 상태가 되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 한 번도 연장하지 않은 풍선, **When** 관리 화면을 보면, **Then** 그 행에 만료일(KST,
   'YYYY년 MM월 DD일')과 누를 수 있는 연장 버튼이 보인다.
2. **Given** 한 번도 연장하지 않은 풍선, **When** 연장 버튼을 누르면, **Then** 만료 시각이 7일 늘어나고
   그 행의 만료일 표시가 갱신되며 연장 버튼은 "연장 완료" 상태로 비활성화된다.
3. **Given** 이미 한 번 연장한 풍선, **When** 다시 연장을 시도하면(화면 우회 포함), **Then** 거부되고
   만료 시각은 바뀌지 않는다.
4. **Given** 같은 묶음의 다른 풍선, **When** 한 풍선을 연장하면, **Then** 다른 풍선의 만료 시각과
   연장 가능 여부는 바뀌지 않는다.
5. **Given** 이미 만료되었고 한 번도 연장하지 않은 풍선, **When** 관리 화면을 보면, **Then** 그 행에
   "만료됨" 상태와 누를 수 있는 연장 버튼이 보인다.
6. **Given** 이미 만료되었고 한 번도 연장하지 않은 풍선, **When** 연장 버튼을 누르면, **Then** 새 만료
   시각은 누른 시점 + 7일이 되고, 그 풍선의 공유 링크는 다시 열리며 상태는 "유효"로 바뀐다.
7. **Given** 관리 코드를 모르는 사람, **When** 풍선 id만으로 연장을 시도하면, **Then** 거부된다.

---

### Edge Cases

- 받는 사람 입력칸이 10개(상한)에 도달하면 `+` 버튼이 비활성화된다. 화면을 우회해 11명 이상으로
  생성을 요청하면 풍선은 하나도 만들어지지 않는다.
- 받는 사람 이름이 공백만으로 이루어진 경우 빈 칸으로 취급한다. 앞뒤 공백은 저장 시 제거한다.
- 같은 이름의 받는 사람을 여러 번 입력해도 허용하며, 각각 별도의 풍선이 된다.
- 관리 화면에서 같은 풍선을 두 번 연속 삭제(빠른 중복 클릭, 다른 탭에서 이미 삭제)하면 두 번째
  요청은 "이미 삭제된 풍선"으로 처리되고 목록은 최신 상태로 갱신된다.
- 관리 화면에서 이미 삭제된 풍선의 링크 복사·연장을 누르면 목록을 갱신하고 해당 행을 제거한다.
- 관리 화면이 열려 있는 동안 풍선이 만료되면, 다음 갱신 시 "만료됨" 상태로 표시된다.
- v3 이전에 만들어진 기존 풍선은 각자 별개의 묶음(풍선 1개짜리)으로 취급된다. 기존 사용자에게는
  관리 링크가 전달된 적이 없으므로 이 풍선들은 사실상 관리 화면에 진입할 수 없으며, 기존 공유 링크는
  기존과 동일하게 동작한다.
- 생성 버튼을 빠르게 여러 번 눌러도 묶음은 한 번만 만들어진다.

## Requirements *(mandatory)*

### Functional Requirements

**풍선 생성**

- **FR-001**: 만든 사람은 태명·출산 예정일·성별을 한 번만 입력하고, 받는 사람은 1명 이상 여러 명을
  입력할 수 있어야 한다.
- **FR-002**: 받는 사람 입력 화면은 처음에 입력칸 1개("받는 사람 01")로 시작하고, `+` 버튼으로 칸을
  최대 10개까지 추가할 수 있어야 한다. 칸 번호는 항상 01부터 연속된 두 자리 번호로 표시된다. 한 번의
  생성 요청에 받는 사람이 10명을 넘으면 시스템은 생성을 거부해야 한다.
- **FR-003**: 첫 번째 칸을 제외한 모든 칸은 X 버튼으로 제거할 수 있어야 한다. 입력칸은 항상 최소
  1개가 남는다.
- **FR-004**: 모든 받는 사람 칸이 채워져 있어야 생성할 수 있으며, 빈 칸이 있으면 생성하지 않고 해당
  칸을 표시해야 한다.
- **FR-004a**: 생성 중에는 "{태명}의 풍선이 만들어지고 있어요." 로딩 화면을 보여야 하며, 저장이 빨리
  끝나도 최소 2초 동안 유지한 뒤 관리 화면으로 이동해야 한다. 실패 시 받는 사람 입력 화면으로 돌아간다.
- **FR-005**: 시스템은 받는 사람마다 풍선 1개를 만들고, 한 번의 생성으로 만든 풍선을 모두 같은 관리
  코드로 묶어야 한다.
- **FR-006**: 한 번의 생성은 전부 성공하거나 전부 실패해야 한다(일부만 생성된 묶음이 남으면 안 된다).
- **FR-007**: 한 묶음 안의 모든 풍선은 생성 시 같은 만료 시각(생성 시각 + 7일)을 가져야 한다.

**관리 코드 보안**

- **FR-008**: 관리 코드는 추측할 수 없는 무작위 값이어야 하며, 풍선 id나 공유 링크에서 유추할 수
  없어야 한다.
- **FR-009**: 관리 코드와 관리 링크는 받는 사람에게 보이는 화면, 공유 링크, 받는 사람이 호출하는
  응답(풍선 조회, 댓글 조회·작성) 어디에도 포함되면 안 된다.
- **FR-010**: 풍선의 삭제와 연장은 풍선 id와 관리 코드가 모두 일치할 때만 수행되어야 한다. 하나라도
  맞지 않으면 아무것도 바뀌지 않아야 하며, 응답으로 해당 풍선의 존재 여부를 드러내지 않아야 한다.
- **FR-011**: 관리 화면 조회는 관리 코드로만 가능해야 하며, 존재하지 않는 관리 코드에는 "찾을 수 없는
  페이지"를 보여야 한다.

**풍선 관리 화면**

- **FR-012**: 관리 화면은 묶음 안의 풍선을 생성 순서대로 받는 사람 번호·이름과 함께 보여야 한다.
- **FR-013**: 각 풍선 행에서 그 받는 사람의 공유 링크를 복사할 수 있어야 한다.
- **FR-014**: 각 풍선 행은 만료일(KST)과 상태(유효 / 만료됨)를 보여야 한다.
- **FR-015**: 생성 직후 관리 화면에 진입하면 관리 링크 보관 모달이 자동으로 떠야 하고, 모달에서 관리
  링크를 확인·복사할 수 있어야 한다. 모달은 복사에 성공해야만 사라진다(닫기 버튼·바깥 클릭·Esc 없음,
  복사 실패 시에만 보조 닫기 제공). 이후 관리 링크로 재진입할 때는 자동으로 뜨지 않는다.
- **FR-016**: 관리 링크는 만료되지 않는다. 묶음 안의 모든 풍선이 만료되었더라도 관리 화면은 열려야 한다.
- **FR-017**: 관리 화면에서 새 풍선 묶음을 만들러 갈 수 있는 진입점을 제공한다(묶음이 비었을 때 필수).

**삭제**

- **FR-018**: 만든 사람은 관리 화면에서 풍선을 하나씩 삭제할 수 있어야 하며, 삭제 전 한 번 확인을
  받아야 한다.
- **FR-019**: 풍선을 삭제하면 그 풍선의 댓글도 함께 영구 삭제되어야 하며, 복구할 수 없다.
- **FR-020**: 삭제된 풍선의 공유 링크로 접속하면 "찾을 수 없는 페이지"를 보여야 한다.

**연장**

- **FR-021**: 만든 사람은 관리 화면에서 풍선마다 최대 1회 연장할 수 있어야 한다. 만료 전이면 새 만료
  시각은 기존 만료 시각 + 7일, 이미 만료되었으면 연장한 시점 + 7일이다. 즉 새 만료 시각은
  "기존 만료 시각과 연장 시점 중 늦은 쪽 + 7일"이다.
- **FR-022**: 연장 여부는 풍선별로 기록되어, 이미 연장한 풍선의 재연장 요청은 화면 우회 여부와 관계없이
  거부되어야 한다.
- **FR-023**: 연장된 풍선의 공유 링크는 늘어난 만료 시각까지 기존과 동일하게 동작해야 한다(기존 만료
  판정 규칙을 그대로 사용).

**기존 기능과의 관계**

- **FR-024**: 받는 사람이 공유 링크로 이용하는 흐름(풍선 터뜨리기, 결과, 결과 이미지 저장, 댓글)은
  변경 없이 동작해야 한다.
- **FR-025**: v3 이전에 만들어진 풍선의 공유 링크는 기존과 동일하게 동작해야 한다.

### Key Entities

- **풍선(젠더리빌 이벤트)**: 받는 사람 1명에게 보내는 이벤트. 태명, 출산 예정일, 성별, 받는 사람 이름,
  공유 링크, 만료 시각, 생성 시각, 관리 코드를 가진다. 연장 여부는 별도로 저장하지 않고 만료 시각이 생성 시각 + 7일보다
  늦은지로 판단한다. 같은 묶음의
  풍선은 태명·예정일·성별·관리 코드가 같다(공통 정보는 풍선마다 중복 저장하며 수정 기능은 없다).
- **풍선 묶음**: 별도로 저장되는 개체가 아니라, 같은 관리 코드를 가진 풍선들의 집합이다.
- **댓글**: 기존과 동일하게 풍선 1개에 속하며, 풍선이 삭제되면 함께 삭제된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 만든 사람은 받는 사람 5명에게 보낼 풍선을 공통 정보 입력부터 생성 완료까지 2분 이내에
  만들 수 있다.
- **SC-002**: 생성 직후 화면에서 받는 사람별 공유 링크를 복사하는 데 행당 1번의 탭이면 충분하다.
- **SC-003**: 관리 링크로 재접속한 만든 사람의 100%가 생성 직후와 같은 받는 사람 목록을 본다.
- **SC-004**: 받는 사람이 볼 수 있는 모든 화면과 응답에서 관리 코드가 노출되는 경우는 0건이다.
- **SC-005**: 관리 코드 없이 시도한 삭제·연장 요청의 성공률은 0%다.
- **SC-006**: 한 풍선은 어떤 경로로도 2회 이상 연장되지 않는다.
- **SC-007**: v3 배포 후에도 기존(v3 이전) 공유 링크의 100%가 배포 전과 동일하게 동작한다.

## Assumptions

- 로그인 기능은 없으며, 관리 링크를 가진 사람을 만든 사람으로 간주한다. 관리 링크를 잃어버리면 복구
  수단은 없다(모달 안내 문구로 보관을 유도).
- 공통 정보 입력 화면(Step1, Figma 258-2)에서 받는 사람 칸이 빠지고 버튼이 "받는 사람 입력"으로 바뀐다.
  디자인의 패스키 영역과 사람 아이콘은 만들지 않는다. 받는 사람 입력은 별도 화면(Step2, 뒤로 가기 버튼
  포함)이며, 뒤로 가기 시 Step1로 돌아가고 입력값은 유지된다.
- Step1의 기존 업데이트 안내 모달은 그대로 유지한다.
- 받는 사람 이름 길이 제한은 기존 규칙을 그대로 따른다.
- 관리 화면에서 생성 이후 받는 사람을 추가하는 기능은 이번 범위에 포함하지 않는다(디자인에 없음).
  추가가 필요하면 새 묶음을 만든다.
- 공통 정보(태명·예정일·성별)와 받는 사람 이름의 수정 기능은 제공하지 않는다.
- 연장 버튼과 만료일 표시는 Figma 258-106에 아직 그려져 있지 않아, 각 받는 사람 행 안에 기존 스타일로
  배치한다(디자인 확정 시 따름).
- 생성 직후 관리 화면 상단의 풍선 일러스트와 하트 장식은 Figma 258-106을 따르며, 성별과 무관한 공통
  이미지다.
- 기존 v3 이전 풍선의 관리 코드는 무작위 값으로 채워지며 누구에게도 전달되지 않는다.
- 저장소 변경(풍선별 관리 코드 저장, 기존 풍선의 관리 코드 무작위 백필)은 `feature/v3`
  브랜치에 이미 초안이 작성되어 있으며, 계획 단계에서 이 스펙 기준으로 검토한다.
